Request for Proposal (RFP)
LifeStation Caregiver Mobile App – v1.0 Development
Issued By: LifeStation
Proposal Due: March 20, 2026 at 5:00 PM Eastern
Primary Contact: Dan Entin, VP Product & Technology
1. Company Overview
LifeStation is a national provider of Personal Emergency Response Systems (PERS), serving
seniors and caregivers through in-home units, mobile pendants, and smartwatches. As
part of its 2026 strategic priorities, LifeStation is launching its first caregiver-facing mobile
application.
This initiative is designed to:
• Address competitive gaps in caregiver experience (see Medical Guardian, Freeus,
Aloe Care apps)
• Enable customer self-service and reduce cost-to-serve
• Establish the foundation for LifeStation as a Service (LSaaS), including smartphone-
based safety offerings that wouldn’t require a dedicated PERS device
• Create a scalable digital platform for feature expansion through 2027 and beyond
LifeStation is seeking a development partner to design and build v1.0 of the mobile
application, with the potential for a multi-phase engagement.
2. Engagement Overview
LifeStation intends to partner with an experienced mobile development agency to:
• Design and develop the v1.0 mobile application
• Integrate with existing monitoring APIs
• Deliver a scalable, maintainable architecture aligned to future roadmap phases
• Support deployment to the Apple App Store and Google Play (with LifeStation as
publisher of record)
1
This is a work-for-hire engagement. All source code and intellectual property will be owned
exclusively by LifeStation.
Strong performance on v1.0 will position the selected agency for continued development
phases extending through at least 2027.
3. Strategic Context
While v1.0 focuses on core caregiver functionality, the mobile app is foundational to
LifeStation’s broader digital strategy.
Future phases may include:
• Geofencing and alert configuration
• Activity telemetry (steps, heart rate)
• Calling into the PERS device from the mobile app
• Initiating an SOS call from the mobile app
• Medication reminders
• Automated wellness check-ins
• Insight and anomaly detection algorithms
• Smartphone-only safety offerings
The architecture delivered in v1.0 must support extensibility and modular feature
expansion, specifically local connectivity between app and PERS device (via Bluetooth)
and app-only experience where there is no dedicated PERS device.

4.3 Web Application (Parallel Scope)
LifeStation requires delivery of a web-based application aligned to the v1.0 feature set. The
web application would include all core features outlined in Section 4.2, with the exception
of push notifications.
Because this initiative is being developed in React Native, LifeStation expects meaningful
reuse of business logic, UI components, and architectural patterns across mobile and
web. Proposals should assume a shared codebase strategy wherever technically
appropriate.
Vendors must clearly describe:
• Proposed web architecture (e.g., React Native Web or alternative)
• Percentage of anticipated code reuse
• Specific components expected to be shared
• Incremental engineering effort required beyond mobile v1.0
• Any technical limitations that materially reduce reuse
If reuse is limited, vendors must explicitly justify the architectural constraints driving that
limitation. Proposals that treat the web application as a net-new standalone build without
leveraging shared architecture may be viewed as misaligned with project objectives.

5. Technical Requirements

5.2 Infrastructure & Integration
