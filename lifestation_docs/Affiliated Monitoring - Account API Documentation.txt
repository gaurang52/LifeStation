Account API
Introduction
The Affiliated Monitoring Account API provides a simple RESTful interface with
JSON-formatted responses to send and receive account information to Affiliated.
Users of this API are able to read, add, delete, and modify the information associated
with each monitored account. This information directly impacts how accounts are
monitored and what response the monitoring center takes in the event of an
emergency or non-emergency signal.

Connecting to API
The Account API requires https for connection.
The API is at https://[subdomain].alertmessage.com/acct
Environment Subdomain
Production
api
Sandbox
sb

Overview
The API uses OAuth 2.0's password grant type to authenticate users. It has 20
methods.
 Password Update – Update password for API user
 Get Accounts – retrieve a full list of accounts, noting statuses active (A), out
of service(I), and empty (E) (i.e. never-used, empty, provisioned accounts)
 Account Read – retrieve the information for a specific account
 Account Create – populate an empty provisioned account for the first time.
 Account Update – update information in an account that is already in use.
 Account Activate – places an account in service. This step method must be
used to make an account monitored. Note: Only In Service accounts are
monitored.
 Account Deactivate – places an account out of service. Note: Out of Service
accounts are not monitored.
 Account Delete – Places an account out of service and resets it as an empty
provisioned account. This is necessary if account number is reused.
 Account Search – search for an account with search terms
 Get Service Company – get the service company of an account
 Update Service Company – updates the service company for an account
 Contact Create – create a new contact for an account
 Contact Edit – edit specific contact for an account
 Contact Delete – deletes a specific contact from an account

Output
All service requests will output a well formatted JSON string.

Result
Every request that makes changes will return a “result” status. If everything worked
correctly, the status will be “ok”. Otherwise, it will be “error”.

Rate Limiting
The API has a rate limit of 600 requests per minute per IP address. When an IP
address exceeds the rate limit, the API will return the following response:
{

"error": {
"code": 429,
"message": "Rate limit exceeded. Maximum 600 requests per
minute allowed.",
"type": "rate_limit_exceeded",
"retry_after_seconds": 60,
"limit": 600,
}
}

If you receive this error, you may resume making requests after the specified
duration, but it is recommended that you update your integration to accommodate
the rate limit to prevent further interruptions.

Account Create
Populates a never-used, empty, provisioned account for the first time. Account
Create is required the first time data is put into an account
PUT - https://[subdomain].alertmessage.com/acct/[cs_no]
[cs_no] – optional – CS number (account id) of account that is being created. If
[cs_no] is not supplied, an account will be created with [cs_no] assigned by the API.
The selected [cs_no] will be the first alphabetically of the available shell accounts.
Consult with your Account Manager to determine if you should always supply a
[cs_no] or never supply one.
Note: CS numbers are provisioned by Affiliated. You cannot use just any desired
value. Please refer to the CS numbers you receive in the Get Accounts endpoint.
Note: Created accounts are not active and will not be monitored until Account
Activate is run on them.
Note: null can mean specific things. If you are not sure what a value should be and it
is not required, do not send it at all instead of sending it as null.
