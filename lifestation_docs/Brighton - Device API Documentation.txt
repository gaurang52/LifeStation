Device API
Introduction
The Brighton Device API provides a simple RESTful interface with JSON-formatted
responses to send and receive device information to Brighton. Users of this API are
able to read, add, delete and modify the information associated with each device.

Connecting to API
The Device API requires https for connection.
The API is at https://[subdomain].alertmessage.com/device
Environment Subdomain
Production
api
Sandbox
sb

Overview
The API uses OAuth 2.0's password grant type to authenticate users. It has 10
methods.
• Get Devices – Retrieve a list of all devices that the API user has access to
• Device Read – retrieve the information for a specific device
• Device Get Most Recent Information – most recent signal information for a
device
• Device Request Signal – Request that a device send a fresh signal to get its
current status.
• Device Get Fall Detection Status – retrieve Fall Detection status for a
device.
• Device Turn On Fall Detection – Request Fall Detection activation for a
device.
• Device Turn Off Fall Detection – Request Fall Detection deactivation for a
device.
• SIM Read – Retrieve the information about a given SIM card.
• SIM Activate – Request SIM card activation.
• SIM Deactivate – Request SIM card deactivation.

Device Identifiers
Each device can be identified by one of three identifiers
• imei – Device-specific identification number
• uid – ID supplied by partner from their system
• iccid – SIM-specific identification number
All API calls that refer to a specific device will include an [id_type] and an [id] in the
URL, allowing the same service to access a device using any of the identifiers.

Output
All service requests will output a well-formatted JSON string.

Error
If a service requests returns an error, the status will be set to “error” and there will
be an error array comprised of error messages.
e.g.

{
"status": "error",
"error": [
"Could not process device: DEMO102011. Not
authorized to use Device."
]
}

Rate Limiting
The API has a rate limit of 600 requests per minute per IP address. When an IP
address exceeds the rate limit, the API will return the following response:
{
"error": {
"code": 429,
"message": "Rate limit exceeded. Maximum 600 requests per
minute allowed.",
"type": "rate_limit_exceeded",
"retry_after_seconds": 60,
"limit": 600,
}
}

If you receive this error, you may resume making requests after the specified
duration, but it is recommended that you update your integration to accommodate
the rate limit to prevent further interruptions.

Request Throttling
There is a limit of 5 requests per device per day.
There is a limit of 500 requests per partner per day.

SIM Read
Get information about a SIM card. This feature is only available if Affiliated manages
the SIM cards for your devices.
GET – https://[subdomain].alertmessage.com/sim/[id_type]/[id]
[id_type] – The type of identifier used to identify the device (‘imei’, ‘iccid’ or ‘uid’).
[id] – The identifier of the device.
cURL Example
curl -X GET
https://[subdomain].alertmessage.com/sim/[id_type]/[id]/
-H 'authorization: Bearer [access_token]' -H 'cache-control: nocache' -H 'accept: application/json'

Response
JSON sim object
status – the status of the response. Should be "ok". If there is an error, it will be
"error"
errors – an array of error messages
sim – an object of sim information
ICCID – the SIM’s ID
uid – ID supplied by partner from their system
cs – the Central Station number, aka the account number
SIM_Status – The current status of the SIM card. (e.g. "Active", "Inactive",
"Activation pending", "Deactivation pending")
e.g.
{
"status": "ok",
"errors": [],
"sim": {
"ICCID":"b2b2b2b2b2b2b2b2b2b2",
"uid":"partnerID",
"cs":"DEMO1000",
"Caller_ID":"123123123",
"IMEI":"c3c3c3c3c3c3c3c3c3c3",
"SIM_Status":"Active"
}
}
