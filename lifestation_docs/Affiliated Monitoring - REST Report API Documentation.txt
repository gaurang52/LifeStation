REST Report API
Introduction
The Affiliated Monitoring Report API provides a simple RESTful interface to receive
alarm activity reports and data from Affiliated. Users of this API are able to retrieve
activity data on individual accounts or for all of their accounts.

Connecting to API
The Report API requires https for connection.
The API is at https://[subdomain].alertmessage.com/report
Environment Subdomain
Production
api
Sandbox
sb

Overview
The API uses OAuth 2.0's password grant type to authenticate users. It currently has
5 methods.
• Get Recent History– Get 50 most recent event signals for an account
• History Create– Request a history report
• History Ready– Check to see if a history report is ready
• History Get – Retrieve history report.
• Get Signal Type – get a list of available signal types for filtering.

Refresh tokens are valid for 30 days from the time of issue.

Throttling
You are limited in how many report requests you can make per hour. Recent
History and History Create have different limits, with Recent History’s limit being
significantly higher. To learn your limits or to request an increase, please contact
Account Management.

Output
All output from the API is a JSON object. It will always include a “result” value, which
will be “ok” if the process ran correctly.
e.g. {
"result": "ok",
"report_id": 8933
}

If there is an error, “result” will be “error” and an “msg” object with a description of
the error will be returned.
e.g. {
"result": "error",

POST Data
If the service request requires POST data, it is passed as raw POST data comprised
of a JSON string. If this document designates a POST variable as optional, that
variable should not be included in the JSON string, unless it is being used. NULL and
FALSE values for passed variables will affect the output of a service call.

Rate Limiting
The API has a rate limit of 600 requests per minute per IP address. When an IP
address exceeds the rate limit, the API will return the following response:
{
"error": {
"code": 429,
"message": "Rate limit exceeded. Maximum 600 requests per
minute allowed.",
"type": "rate_limit_exceeded",
"retry_after_seconds": 60,
"limit": 600,
}
}

If you receive this error, you may resume making requests after the specified
duration, but it is recommended that you update your integration to accommodate
the rate limit to prevent further interruptions.
